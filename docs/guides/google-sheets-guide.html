۱) این اتصال چه کاری انجام می‌دهد؟

سامانه هر روز ساعت ۰۳:۰۰ به‌وقت تهران فهرست خودروها را از شیت Google مجموعه می‌خواند و با پایگاه‌دادهٔ خود تطبیق می‌دهد. این خوانش فقط‌خواندنی است: هیچ‌چیز از سامانه به شیت نوشته نمی‌شود و بدهی‌ها، محدودیت‌های داخلی و مجوزهای فعلی خودروها هرگز توسط همگام‌سازی تغییر نمی‌کنند. ردیف‌هایی که پلاک نامعتبر، کلید تکراری یا مغایرت پلاک دارند، به‌جای اعمال خودکار به «صف تعارض» می‌روند و فقط با تصمیم انسانی (اعمال یا رد با یادداشت) تعیین تکلیف می‌شوند.

موردمقدار
جهت همگام‌سازیشیت → سامانه (فقط‌خواندنی، غیرتخریبی)
شیت خودروهاdocs.google.com/spreadsheets/d/1ZbiQl_9nab-CH0uR1i9dq6pevcCvY0SfyUuxpIyEjQQ
نام تب (worksheet)«خودروها» (قابل تغییر هنگام نصب)
زمان اجرای خودکارروزانه ۰۳:۰۰ تهران (در صورت بالابودن بک‌اند)
پیش‌نیاز فنیفایل JSON حساب سرویس در secrets/service-account.json
چه کسانی این راهنما را اجرا می‌کنند؟ مدیر سامانه که به حساب Google مجموعه دسترسی دارد. فقط بار اول ≈۱۵ دقیقه زمان می‌برد؛ دفعات بعد هیچ کاری لازم نیست.

۲) گام ۱ — ساخت حساب سرویس در Google Cloud (≈۵ دقیقه)

«حساب سرویس» (Service Account) یک حساب رباتی Google است که به‌جای کاربر واقعی، شیت را می‌خواند. مراحل:

۱

ورود به Google Cloud Console

به console.cloud.google.com بروید و با حساب Google مجموعه وارد شوید.

۲

ساخت پروژه

از بالای صفحه Select project → New Project؛ نام: parking-arkide → Create. سپس پروژه را انتخاب کنید.

۳

فعال‌سازی API

از منوی کناری APIs & Services → Library؛ جست‌وجوی Google Sheets API → Enable.

۴

ساخت حساب سرویس

APIs & Services → Credentials → + Create Credentials → Service account. نام: parking-readonly. نقش (Role) لازم نیست — Skip را بزنید → Done.

۵

دریافت فایل کلید JSON

در فهرست Service accounts روی حساب ساخته‌شده کلیک کنید → تب Keys → Add key → Create new key → JSON → Create. یک فایل .json دانلود می‌شود. ایمیل حساب (شبیه parking-readonly@parking-arkide.iam.gserviceaccount.com) را یادداشت کنید — در گام بعد لازم است.

⚠ امنیت: این فایل معتبرِ ورود است؛ به هیچ‌کس ندهید و در مخزن کد کامیت نکنید (پوشهٔ secrets/ در .gitignore رزرو شده است).

۳) گام ۲ — اشتراک‌گذاری شیت با حساب سرویس (فقط‌خواندنی)

  1. شیت خودروها را باز کنید: https://docs.google.com/spreadsheets/d/1ZbiQl_9nab-CH0uR1i9dq6pevcCvY0SfyUuxpIyEjQQ
  2. دکمهٔ Share → ایمیل حساب سرویس (گام ۱-۵) را وارد کنید → نقش Viewer → Send.
  3. نام دقیق تب (worksheet) را یادداشت کنید. پیش‌فرض سامانه: «خودروها».
نقش Viewer کافی است چون همگام‌سازی فقط می‌خواند؛ دسترسی Editor یا بالاتر ضروری نیست و توصیه نمی‌شود.

۴) گام ۳ — ستون‌های استاندارد شیت (۲۰ ستون)

سامانه ستون‌ها را با «عنوان سطر اول» می‌شناسد؛ ترتیب ستون‌ها آزاد است و ستون ناشناخته نادیده گرفته می‌شود. عنوان‌ها باید دقیقاً یکی از این ۲۰ مورد باشند:

external_vehicle_id | source_system | plate_raw | plate_normalized |
owner_full_name | owner_mobile | unit_number | tower_code | brand | model |
color | year | vehicle_type | plate_type | permit_type | permit_valid_from |
permit_valid_until | is_active | notes | external_updated_at
ستونتوضیحالزام / قالب
external_vehicle_idشناسهٔ یکتای خودرو در سیستم مبدأالزامی — کلید تطبیق
plate_rawپلاک به همان شکلی که در شیت استالزامی — قالب ایرانی: مثل «۱۲ ب ۳۴۵ ایران ۱۱»
owner_full_name ، owner_mobileنام و موبایل مالکاختیاری
unit_number ، tower_codeشمارهٔ واحد و کد برجاختیاری
brand ، model ، color ، yearمشخصات خودرواختیاری
permit_valid_from / permit_valid_untilبازهٔ اعتبار مجوزمیلادی 2026-10-23 یا شمسی 1405-08-01
is_activeفعال / غیرفعال بودن خودرو«فعال/غیرفعال» یا TRUE/FALSE
notes ، external_updated_atیادداشت و آخرین تغییر مبدأاختیاری
مهم: اگر plate_raw با قالب پلاک ایران مطابقت نکند یا external_vehicle_id تکراری/خالی باشد، آن ردیف اعمال نمی‌شود و در «صف تعارض» پنل همگام‌سازی منتظر تصمیم اپراتور می‌ماند.

۵) گام ۴ — نصب روی سرور با اسکریپت (یک دستور)

فایل JSON حساب سرویس را روی سرور (یا لپ‌تاپ فعلی) در مسیر E:\ParkingSystem\secrets\service-account.json کپی کنید، سپس در PowerShell:

cd E:\ParkingSystem
.\scripts\setup-google-sync.ps1 -KeyPath .\secrets\service-account.json -Worksheet "خودروها"

این اسکریپت به‌ترتیب چهار کار انجام می‌دهد:

  • [۱] اعتبارسنجی ساختار فایل JSON (وجود client_email و private_key)
  • [۲] کپی امن فایل به secrets\service-account-readonly.json و اطمینان از خارج‌بودن آن از git
  • [۳] نوشتن تنظیمات در backend\.env (شناسهٔ شیت، نام تب، ساعت اجرا، فعال‌سازی همگام‌ساز) بدون بازنویسی بقیهٔ تنظیمات
  • [۴] تست اتصال واقعی به شیت از طریق API بک‌اند (اگر بک‌اند بالا باشد) — خروجی موفق: نام شیت + فهرست تب‌ها + ایمیل حساب سرویس
خروجی موفق: ✔ اتصال موفق! شیت: «…» | تب‌ها: … — اگر بک‌اند آن لحظه بالا نبود، نگران نباشید: تنظیمات ذخیره شده و می‌توانید بعد از اجرای سامانه، تست را از خود پنل بزنید (گام ۵).

۶) گام ۵ — اجرا و کنترل از داخل پنل

با حساب admin وارد شوید → منوی «همگام‌سازی و انطباق» → «همگام‌سازی خودروها (Sheets)». در این صفحه:

  • تست اتصال — یک فراخوانی سبک به شیت؛ نام شیت و تب‌ها را نشان می‌دهد. بعد از نصب اول این را بزنید.
  • اجرای آزمایشی (Dry-run) — ردیف‌های شیت را می‌خواند و گزارش می‌دهد «چه چیزی تغییر می‌کرد» بدون هیچ تغییری در پایگاه‌داده. پیش از اجرای واقعی حتماً یک‌بار Dry-run بزنید.
  • اجرای همگام‌سازی — اعمال واقعی (upsert غیرتخریبی) با ثبت در تاریخچه.
  • صف تعارض — ردیف‌های پلاک نامعتبر / کلید تکراری / مغایرت پلاک؛ هر مورد فقط با دکمهٔ «اعمال» یا «رد» (به‌همراه یادداشت) و توسط انسان تعیین تکلیف می‌شود.
  • تاریخچهٔ اجراها — وضعیت اجرای روزانهٔ ۰۳:۰۰ و اجراهای دستی.
  • گزارش انطباق — کارت پوشش sync، تعارض باز و آخرین اجرا.

۷) عیب‌یابی سریع

خطا / نشانهعلت و راه‌حل
فایل حساب سرویس خوانده نشدمسیر -KeyPath اشتباه است — مسیر دقیق فایل JSON را بدهید.
403 PERMISSION_DENIEDشیت با ایمیل حساب سرویس به‌اشتراک گذاشته نشده — گام ۲ را تکرار کنید (نقش Viewer).

اجرای ۰۳:۰۰ انجام نشددر آن ساعت بک‌اند باید بالا باشد. «تاریخچهٔ اجراها» در پنل و لاگ بک‌اند را ببینید: docker compose -f docker-compose.prod.yml logs backend
ردیف‌ها در صف تعارض می‌مانندپلاک یا شناسهٔ آن ردیف‌ها مشکل دارد — روی هر مورد «جزئیات» را باز کنید؛ با اصلاح در شیت، اجرای بعدی درست می‌شود.

۸) امنیت و نگهداری

  • فایل JSON = کلید ورود ربات است. فقط در پوشهٔ secrets/ نگه دارید؛ این پوشه در .gitignore است و هرگز به git یا چت منتقل نمی‌شود.
  • اگر احتمال لو رفتن کلید دادید، در Google Cloud → تب Keys کلید را Delete کنید و کلید جدید بسازید (نصب مجدد اسکریپت لازم است).
  • برای تغییر شیت یا تب فقط کافی است اسکریپت گام ۴ را با پارامترهای جدید اجرا کنید — تنظیمات قبلی جایگزین می‌شود.
  • هر تغییر در شیت حداکثر تا ۲۴ ساعت بعد (اجرای ۰۳:۰۰) یا فوراً با «اجرای همگام‌سازی» از پنل اعمال می‌شود.
