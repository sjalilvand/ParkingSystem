۱) معماری سامانه در یک نگاه

کل سامانه با Docker اجرا می‌شود؛ پنج سرویس زیر روی سرور بالا می‌آیند و داده‌ها در volumeهای داکر ذخیره می‌شوند. فرانت‌اند نهایی (نسخهٔ build شده) داخل همان کانتینر nginx سرو می‌شود و نیازی به نصب Node روی سرور نیست.

سرویسنقشتوضیح
nginxدرگاه وبصفحهٔ سامانه + پروکسی API و WebSocket روی پورت APP_PORT (سرور: 80)
backendمغز سامانه (FastAPI)مهاجرت‌های خودکار + بوت‌استرپ + API؛ دو worker
postgresپایگاه‌دادهخودروها، تردد، مالی و… در volume pgdata
redisکش و صفپیام‌رسانی لحظه‌ای و صف کارها
minioفایل‌سرورعکس خودروها و اسناد در volume miniodata
مرورگر کاربر← nginx :80← backend :8000← postgres / redis / minio

۳) گام ۱ — نصب نرم‌افزارهای پایه

۱

Docker Desktop for Windows

از docker.com/products/docker-desktop دانلود و نصب کنید (گزینهٔ WSL2 backend). پس از نصب، دو تنظیم حیاتی زیر را انجام دهید — تجربهٔ ما روی لپ‌تاپ نشان داد آپدیت خودکار = فلپ موتور داکر:

# در PowerShell — خاموش کردن دانلود خودکار آپدیت (علت اصلی ناپایداری موتور)
$sf = "$env:APPDATA\Docker\settings-store.json"
$j = Get-Content $sf -Raw | ConvertFrom-Json
$j | Add-Member -NotePropertyName AutoDownloadUpdates -NotePropertyValue $false -Force
$j | ConvertTo-Json -Depth 20 | Set-Content $sf -Encoding utf8

در Settings → General گزینهٔ Start Docker Desktop when you sign in را فعال کنید تا بعد از ری‌استارت سرور، سامانه خودش بالا بیاید.

۲

Git for Windows

از git-scm.com/download/win نصب کنید (گزینه‌های پیش‌فرض کافی است).

۳

PowerShell 7

از aka.ms/powershell نصب کنید و همهٔ دستورها را در آن بزنید (سازگاری کامل با متن فارسی).

۴) گام ۲ — دریافت سورس از GitHub

cd E:\
git clone https://github.com/sjalilvand/ParkingSystem.git ParkingSystem
cd E:\ParkingSystem
git config --global --add safe.directory E:/ParkingSystem
git log --oneline -3        # باید آخرین کامیت‌ها را نشان دهد
اگر خطای «dubious ownership» دیدید یعنی safe.directory را هنوز نزده‌اید — همان خط بالا را اجرا کنید. اگر مسیر پروژه روی سرور C: یا درایو دیگری است، در همهٔ دستورهای این راهنما مسیر را متناسب عوض کنید.

۵) گام ۳ — ساخت فایل .env.prod

از نمونهٔ آماده کپی بگیرید و مقادیر <GENERATE> را پر کنید:

Copy-Item .env.prod.example .env.prod
notepad .env.prod
متغیرمقدار روی سرورتوضیح
APP_SECRET_KEY / JWT_SECRET_KEYرشتهٔ تصادفی بلندتولید: -join ((48..57)+(97..122) | Get-Random -Count 48)
POSTGRES_PASSWORDرمز قویاین همان رمزی است که در گام ۴ به سرور منتقل می‌شود؛ بعداً تغییرش ندهید (§۱۱-ب)
POSTGRES_USER / POSTGRES_DBparking / parking_dbپیش‌فرض — دست نزنید
DEFAULT_ADMIN_PASSWORDرمز قوی ادمینفقط بار اول ساخته می‌شود؛ جایی امن یادداشت کنید
MINIO_SECRET_KEYرمز قویباید با لپ‌تاپ یکی باشد تا فایل‌ها import شوند
GATE_API_KEYرشتهٔ تصادفیکلید ارتباط گیت‌ایجنت با بک‌اند
APP_PORT80روی سرور 80 تا کاربران فقط http://192.168.100.2 بزنند (اگر 80 اشغال است: 8880)
CORS_ALLOWED_ORIGINShttp://192.168.100.2همان آدرسی که کاربران باز می‌کنند
نکتهٔ طلایی: رمزهای POSTGRES_PASSWORD و MINIO_SECRET_KEY را از لپ‌تاپ عیناً کپی کنید. رمز دیتابیس فقط در «بار اول ساخت volume» ثبت می‌شود و اگر بعداً در فایل عوضش کنید، اتصال بک‌اند می‌شکند (راه‌حل: §۱۱-ب).

۶) گام ۴ — انتقال داده‌ها از لپ‌تاپ به سرور

داده‌های واقعی (۵۰۷ خودرو + عکس‌ها) در volumeهای داکر لپ‌تاپ هستند و با git منتقل نمی‌شوند. دو اسکریپت آمادهٔ deploy/ این کار را انجام می‌دهند:

لپ‌تاپ: export-data.ps1← فایل zip روی دسکتاپ← کپی با فلش/شبکه← سرور: import-data.ps1
۱

روی لپ‌تاپ — خروجی‌گیری

cd E:\ParkingSystem
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d
powershell -File deploy\export-data.ps1

اسکریپت خودش استک production را تشخیص می‌دهد، dump دیتابیس می‌گیرد، عکس‌های MinIO را mirror می‌کند و parking-migration-…zip را روی دسکتاپ می‌گذارد.

۲

انتقال فایل

فایل zip را با فلش یا شبکه به سرور ببرید و از حالت فشرده خارج کنید (مثلاً C:\parking-migration شامل parking_backup.sql و پوشهٔ minio).

۳

روی سرور — بازگردانی

cd E:\ParkingSystem
# اول postgres به‌تنهایی بالا بیاید:
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d postgres
powershell -File deploy\import-data.ps1 -BackupDir "C:\parking-migration"

خروجی موفق: vehicles rows restored: 507 و MinIO restore OK.

۷) گام ۵ — استقرار با یک دستور

cd E:\ParkingSystem
.\UPDATE-AND-RUN.ps1 -Prod

این اسکریپت همهٔ کارها را خودکار انجام می‌دهد:

گام اسکریپتکار
[۱]git pull از GitHub (تغییرات محلی موقتاً stash و بعد برگردانده می‌شود)
[۲]آماده‌سازی venv — در حالت Prod فقط برای گیت‌ایجنت است؛ خطای پایتون/venv مانع استقرار نمی‌شود
[۳]مهاجرت‌های دیتابیس — در Prod داخل کانتینر و با migrate_prod_safe.py اجرا می‌شود (امن برای دیتابیس‌های قدیمی)
[۴]build فرانت‌اند — داخل کانتینر nginx هم build مجدد می‌شود
[۵]توقف اجراهای قبلی و آزادسازی پورت‌ها
[۶]بک‌آپ خودکار دیتابیس + docker compose up -d --build
[۹]بررسی سلامت تا ۶۰ ثانیه از /health/live و چاپ آدرس نهایی
خروجی موفق: «✔ سامانه در حالت production سالم است.» و «آدرس سامانه: http://192.168.100.2» — کد خروج ۰. اگر کد ۲ شد، هنوز سلامت نیست؛ §۱۱ را ببینید.

از این لحظه چک‌لیست بازبینی (docs/menu-review-checklist.md نسخهٔ ۲) را روی سرور ادامه دهید — ستون «میدانی E:» همان‌جاست.

۹) اجرای خودکار پس از ری‌استارت سرور

  • همهٔ سرویس‌ها restart: unless-stopped دارند: هر وقت موتور داکر بالا بیاید، خودشان برمی‌گردند.
  • Docker Desktop را در Settings → General روی Start when you sign in بگذارید (گام ۱).
  • اگر سرور رمز کاربر دارد و لاگین خودکار نمی‌خواهید، کافی است بعد از هر بوت یک‌بار Docker Desktop را باز کنید — بقیه‌اش خودکار است.

۱۰) پشتیبان‌گیری منظم

قبل از هر به‌روزرسانی، UPDATE-AND-RUN.ps1 خودش بک‌آپ می‌گیرد؛ برای بک‌آپ روزانهٔ خودکار، Task Scheduler را تنظیم کنید:

# ساخت وظیفهٔ روزانهٔ ۰۳:۳۰ (بعد از sync گوگل):
schtasks /Create /TN "ParkingBackup" /SC DAILY /ST 03:30 /RL HIGHEST `
  /TR "powershell -NoProfile -ExecutionPolicy Bypass -File E:\ParkingSystem\scripts\backup-db.ps1"

بک‌آپ‌ها را هفته‌ای یک‌بار روی دیسک/فلش خارج از سرور هم کپی کنید. برای بازگردانی: deploy\import-data.ps1 -BackupDir <مسیر>.

۱۱) عیب‌یابی‌های شناخته‌شده (تجربهٔ واقعی استقرار)

نشانهعلتراه‌حل
failed to connect … npipe:////./pipe/dockerDesktopLinuxEngineDocker Desktop روشن نیست (نصب per-user است و ممکن است مسیر پیش‌فرض نباشد)Docker Desktop را از Start Menu اجرا کنید و تا سبز شدن Engine صبر کنید؛ سپس دستور را تکرار کنید.
موتور داکر چند دقیقه بعد از بالا آمدن دوباره می‌افتدآپدیت خودکار Docker Desktopقطعهٔ کد AutoDownloadUpdates=false در گام ۱ — دقیقاً همین مشکل روی لپ‌تاپ حل شد.
dubious ownership in repositoryمالک پوشه با کاربر فعلی فرق داردgit config --global --add safe.directory E:/ParkingSystem
backend بالا نمی‌آید و لاگ می‌گوید InvalidPasswordErrorرمز volume با .env.prod نمی‌خواند، یا دستور compose را بدون --env-file .env.prod زده‌اید (مثلاً docker compose -f docker-compose.prod.yml up -d backend)یک‌دستوری: .\scripts\prod-repair.ps1 — رمز volume را با .env.prod همگام می‌کند (ALTER USER)، backend/nginx را با --env-file دوباره بالا می‌آورد و سلامت را چک می‌کند؛ بدون آسیب به داده‌ها. اگر باز هم خطا بود: docker compose -f docker-compose.prod.yml exec postgres psql -U parking -d parking_db -c "ALTER USER parking WITH PASSWORD 'رمز-env.prod';"
پورت 80 پاسخ نمی‌دهد یا می‌خواهید پورت را عوض کنید (مثلاً 8080 → 8085)APP_PORT در .env.prod چیز دیگری است، یا nginx با --env-file بالا نیامدهیک‌دستوری: .\scripts\prod-repair.ps1 -Port 8085 — مقدار APP_PORT را در .env.prod عوض و nginx را با همان بازسازی می‌کند. (بررسی دستی: Select-String "^APP_PORT" .env.prod)
لاگ backend: DuplicateTableError: relation "uq_open_session_plate" already exists → 502 برای همهٔ endpoint هانسخه‌های قدیمی مهاجرت p0001 غیر-idempotent بودند؛ ایندکس از قبل (با bootstrap) ساخته شده ولی رکورد alembic نبوداز نسخهٔ 873959b به بعد خودکار حل شده — فقط git pull و .\scripts\prod-repair.ps1. داده‌ها دست‌نخورده می‌مانند.
لاگ backend: ModuleNotFoundError: No module named 'cv2' هنگام بوت → 502نسخه‌های قدیمی plate_ocr/router.py در سطح ماژول import cv2 داشتند؛ تصویر Docker عمداً سبک است (OCR اختیاری)از نسخهٔ جاری به بعد خودکار حل شده — اپ بدون OCR هم بوت می‌شود و صفحهٔ پلاک‌خوان پیام راهنما می‌دهد. برای فعال‌سازی پلاک‌خوان داخل کانتینر: خط INSTALL_OCR=true را به .env.prod اضافه کنید و .\scripts\prod-repair.ps1 را بزنید (بار اول مدل‌ها دانلود می‌شوند).
بیلد در مرحلهٔ OCR خیلی طول می‌کشد یا «متوقف» به نظر می‌رسد (دانلود torch و بسته‌های nvidia-*)نسخه‌های قدیمی Dockerfile بیلد CUDA‌ی torch را از PyPI نصب می‌کردند — چند گیگابایت کتابخانهٔ انویدیا؛ روی سرور بدون GPU کاملاً بیهوده و با اینترنت کند ساعت‌ها طول می‌کشداز نسخهٔ جاری به بعد خودکار حل شده — Dockerfile همیشه «torch CPU» (~۲۲۰MB از download.pytorch.org/whl/cpu) را نصب می‌کند؛ EasyOCR روی CPU کامل کار می‌کند. اگر بیلد قدیم وسط کار مانده: Ctrl+C → git pull → .\scripts\prod-repair.ps1 (بی‌خطر است؛ داده‌ها دست‌نخورده).
تب «نقشه CAD (DXF)» خالی است و همهٔ شمارنده‌ها صفرندجایگاه‌های DXF هنوز وارد دیتابیس نشده‌اند (فایل JSON در build context کانتینر نبود)راه فوری بدون به‌روزرسانی: در همان تب دکمهٔ «بارگذاری خروجی AI (JSON)» را بزنید و فایل E:\ParkingSystem\docs\cad\parking_spots_import.json را انتخاب کنید. یا: git pull + .\scripts\prod-repair.ps1 — از این نسخه، bootstrap بار اول خودش جایگاه‌ها را seed می‌کند (۶۱ قلم نقشهٔ واقعی planYARD: ۵۶ جای سطحی در ۹ ردیف + فوت‌پرینت واقعی بلوک‌های A/B/C + مرز سایت)؛ re-seed وضعیت‌های دستی اپراتور را بازنویسی نمی‌کند.
جایگاه‌ها روی نقشهٔ CAD پخش‌شده و نامرتب‌اند (جایگاه‌های A-xx روی بلوک A افتاده‌اند و ردیف‌های B-S/C-S با سایت‌پلان واقعی نمی‌خوانند)نسخهٔ قدیمی JSON جایگاه‌ها را از نقشهٔ طبقه ‎-۲‎ (TA_P2.dxf) با تبدیل تقریبی «روی سایت‌پلان منتقل» می‌کرد و ردیف‌های سطحی از جفت‌خطوط بازسازی شده بودند — هندسهٔ TA_P2 نیز از INSERTهای کشیده‌شدهٔ چندجایگاهی در یک نقطه تشکیل شده و قابل اعتماد نیستاز این نسخه JSON از هندسهٔ واقعی planYARD.dxf (همان سایت‌پلان کارفرما) بازسازی شده: ۵۶ جای سطحی واقعی در ۹ ردیف (عمود و مورب ۴۵ درجه) + فوت‌پرینت واقعی بلوک‌ها. جایگزینی روی سرور — راه فوری بلافاصله پس از git pull (بدون نیاز به بیلد): در تب CAD اول «پاک‌سازی همه» بعد «بارگذاری خروجی AI (JSON)» و انتخاب E:\ParkingSystem\docs\cad\parking_spots_import.json. یا یک‌دستوری پس از یک بار اجرای UPDATE-AND-RUN.ps1 -Prod (تا کد جدید اسکریپت داخل کانتینر برود): docker compose -f docker-compose.prod.yml --env-file .env.prod exec backend python -m scripts.import_cad_spots --purge
رمز ادمین فراموش شده (401 در صفحهٔ ورود)رمز کاربر admin قبلاً عوض شده و در دسترس نیستروی سرور (رمز دلخواه، حداقل ۸ کاراکتر — در PowerShell از کوتیشن تک استفاده کنید): docker compose -f docker-compose.prod.yml --env-file .env.prod exec backend python -m scripts.reset_admin --password 'NewPass@2026' — خروجی باید بگوید admin password UPDATED. فقط هش رمز عوض می‌شود؛ داده‌ها دست‌نخورده می‌مانند.

۱۲) به‌روزرسانی‌های بعدی

هر وقت نسخهٔ جدیدی روی GitHub قرار گرفت، روی سرور فقط همین را بزنید:

cd E:\ParkingSystem
.\UPDATE-AND-RUN.ps1 -Prod

اسکریپت قبل از ارتقا خودش بک‌آپ می‌گیرد، آخرین کد را می‌کشد و سرویس‌ها را بدون از دست رفتن داده جایگزین می‌کند. داده‌ها در volumeها هستند و با build یا pull جدید آسیب نمی‌بینند.
